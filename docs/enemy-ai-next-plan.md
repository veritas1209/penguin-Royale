# 적 AI 전술 개편안

상태: 설계·검증 계획만 작성했다. 아래 전술은 아직 실서버에 적용하지 않았다. 훈련장과 실전은 같은 Raid 전투 코드를 쓴다. 대응 소대 장비 반복 문제는 별도로 수정·배포됐다.

## 현재 문제와 원인

| 경험 | 코드에서 확인한 원인 | 수정 방향 |
| --- | --- | --- |
| 건물로 들어가면 보스가 안 따라옴 | 보스 목표 선택은 목표까지 직선거리가 사거리 안이면 벽과 관계없이 멈춘다. 마지막 위치에 도착한 뒤 실내 수색도 없다. | 문 연결점을 거쳐 추격하고, 모서리·실내 마지막 목격 지점을 수색한다. |
| 무배율 화면 밖에서 피격 | 일반 저격수만 발사 전 화면 경계를 검사한다. 대응 소대 저격수는 예외이고 검사 기본 범위도 8배율 확장값이다. 보스·저격수의 발견 거리는 80~96m다. | 발견·추적·피해를 주는 발사를 분리하고 실제 카메라 경계를 적용한다. |
| 질주하면 사격을 피하기 쉬움 | 선행 조준은 현재 입력 방향, 예상 비행시간, 0.72 배율로 이미 구현돼 있다. 관측 이동을 통한 보정은 없다. | 짧은 구간에서 실제 관측 속도를 추정하고 예측 상한과 단계별 오차를 둔다. |
| 모서리에서 벽 너머 칼 공격 가능 | 플레이어 근접 공격은 거리와 140도 각도만 검사하고 벽을 검사하지 않는다. 대응 소대는 시야가 끊겨도 플레이어 현재 좌표를 매 틱 공유한다. | 모든 직접 타격에 장애물 검사를 적용하고 확인한 위치만 공유한다. |

## 공통 판정과 정보 모델

1. 총알, 일반·전설 근접 공격, 적의 직접 공격에 통일된 벽·문·창문 통과 규칙을 적용한다. 닫힌 문 뒤 대상은 가까워도 맞지 않는다.
2. 접촉 정보를 대상, 마지막 확인 좌표, 출처(직접 시야·소리·피격·동료 제보), 시각, 신뢰도로 기록한다. 시야가 끊기면 마지막 좌표를 고정하고 시간이 지나면 신뢰도를 낮춘다. 소리는 정확한 현재 좌표가 아닌 위치 추정만 제공한다. 제보는 원래 관측보다 정확해질 수 없다.
3. 발견 반경은 수색 시작에만 사용한다. 피해를 주는 첫 사격은 유효한 사선, 반응 지연, 화면 내 적 위치를 모두 만족한다. 무배율 화면 밖 피격은 0을 목표로 한다. 견제 사격은 마지막 목격 지점·문·엄폐 가장자리로만 발사하고 정상 탄환·탄약·벽 판정을 사용한다.
4. 월드 건물의 문 위치와 벽 충돌로 출입구 안팎 연결점을 맵 로드 시 한 번 생성한다. 잠긴 문은 통과 경로에서 제외한다. 목표가 실내에 있으면 문까지 이동한 뒤 실내 경로를 찾는다.
5. 사격은 최근 0.2~0.4초의 관측 속도로 비행시간만큼 제한적으로 앞을 겨눈다. 방향 전환·거리·연사 오차와 예고 시간을 유지하고 시야가 끊긴 현재 입력을 이용한 정밀 추적은 금지한다.

1단계 일반 적의 순찰·교전 전술은 유지한다. 공통 벽·시야·피해 공정성 수정만 함께 받는다.

## 단계별 행동

| 단계 | 대상 | 행동 | 플레이어 대응 |
| --- | --- | --- | --- |
| 1 | 일반 적 | 현행 전술 유지 | 기존 반응 시간과 엄폐 효과 |
| 2 | 보스 | 목격 → 문까지 추격 → 실내 진입 → 마지막 위치와 1~2개 모서리 수색 → 재탐색 또는 포기. 직선거리가 가까워도 벽 너머라면 멈추지 않는다. | 문 진입 전 움직임을 보고 다른 출구로 이탈 가능 |
| 3 | 증원 소대·저격수 | 마지막 확인 좌표를 분대와 공유한다. 한 명은 접근하고 다른 인원은 문·엄폐 가장자리를 견제한다. 저격수는 피격 또는 몇 차례 발사 뒤 다른 사선·엄폐를 찾는다. | 엄폐 뒤 정밀 피격이 없고 견제 방향을 확인 가능 |
| 4 | 대응 소대 | 현행 엄호·돌입·측면·저격 역할을 경로, 엄폐, 사선, 분대 간격으로 조정한다. 유효 접촉이 있을 때만 협동 돌입하고, 시야가 끊기면 마지막 위치 수색 후 재편성한다. | 동시 돌입 인원·사격 간격 제한, 측면 이동 예고 |

보스는 따라오는 능력, 증원은 불확실한 위치를 압박하는 능력, 대응 소대는 역할 조율로 차별화한다. 사거리 증가·벽 투시·체력 증가는 난이도 수단으로 쓰지 않는다.

## 구현·검증 순서

1. 공통 피해 판정과 화면 밖 발사 제한을 먼저 수정한다. 건물 문, 잠긴 문, 창문, 모서리, 모바일·PC 화면과 조준경별 경계 테스트를 둔다.
2. 시야·소리·피격의 출처를 포함한 접촉 기록을 만든다. 플레이어가 시야 밖에서 움직여도 마지막 확인 좌표가 따라 움직이지 않는지 검증한다.
3. 보스의 문 연결점과 실내 추격을 추가한다. ㄱ자 모서리, 막힌 문, 대체 출입구, 경로 없음 시나리오를 훈련장에서 검증한다.
4. 증원 제보·견제 사격·저격수 재배치를 추가한다. 숨은 플레이어의 정확한 현재 위치를 겨냥하지 않는지 기록한다.
5. 대응 소대 역할과 위치 점수, 동시 돌입 상한을 적용한다. 교전·수색·철수의 전환을 확인한다.
6. 걷기·질주·좌우 방향 전환별 명중률, 첫 피격까지 시간과 처치 시간을 측정해 튜닝한다. 질주만으로 계속 무피해인 상황은 줄이되 화면에 들어온 직후 즉사는 허용하지 않는다.

필수 자동 시나리오는 벽 너머 근접 피해 0, 실내 문 추격, 시야 상실 뒤 위치 고정, 무배율 화면 밖 피격 0, 저격 피격 뒤 재배치, 질주 목표의 부분 명중, 대응 소대 동시 돌입 상한이다. 각 단계는 훈련장 검증 뒤 별도로 운영 적용을 결정한다.

## Jetson Orin Nano 예산

현행 서버는 50ms 게임 틱, 100ms AI 틱, 주변 120m 활성화, AI 틱당 경로 탐색 최대 4건, 약 6ms 탐색 마감, A* 최대 360노드와 경로 재사용 정책을 사용한다. 이 상한을 유지한다. 문 연결점은 맵 로드 시 한 번 생성하고, 전술 재선택은 0.25~0.5초 간격으로 분산한다. 후보는 값싼 거리·충돌 검사로 걸러 상위 2~3곳만 사선·경로를 확인한다. 처리 예산 초과 시 재선택 주기만 낮춘다. 벽·시야·피해 판정은 생략하지 않는다.

운영 서버의 유휴 CPU/RSS 수치는 실전 기준이 아니다. 같은 맵과 장비에서 1명/4명, 적 수, 교전 강도를 맞춘 10분 이상 시나리오로 적용 전후 틱 지연, 탐색 시간, CPU, RSS를 비교한다. 임시 기준은 50ms 틱 내 처리, 기존 경로 예산 유지, p95 틱 지연 증가 3ms 미만, 지속 RSS 증가 30MB 이하이다. 기준은 실측 후 확정한다. 행동과 성능을 모두 통과하지 못한 단계는 훈련장에만 둔다.
